# TAPAS Growth Autopilot v1.6 — Publishing, Distribution & Client Growth Target

## Client requirement
TAPASLEARNING requires a single operational workflow that prepares and publishes approved LinkedIn posts and YouTube videos, distributes each published asset through authorized channels, coordinates engagement workflows without fake engagement, and measures progress toward a minimum campaign target of 5,000 YouTube views per video.

## Current code baseline (verified against main)
- Release tag: v1.5.1.
- Main commit: b2642979e5198c18403825aa420065df9b92fb58.
- Auto-publish is approval-gated.
- LinkedIn route: personal-profile text posts only.
- YouTube upload: blocked because the existing Google OAuth connection lacks youtube.upload.
- YouTube title/retention/Shorts guidance exists, but is not a video upload path.
- vidIQ, TubeBuddy, ConnectSafely, MagicPost and Supergrow are not yet connected in this repository.

## v1.6 scope
1. Fix runtime release version reporting to 1.6.0 and keep release metadata consistent.
2. LinkedIn publishing readiness:
   - Preserve existing w_member_social personal-profile route.
   - Add a separate organization-page route only when the app has approved organization posting scope and the authenticated user is an authorized page admin.
   - Never infer page capability from user login alone.
3. YouTube upload:
   - Add explicit youtube.upload OAuth scope and a re-consent flow.
   - Implement resumable uploads, metadata, privacy status, and scheduled publication only when the YouTube API supports the requested state.
   - Keep an explicit preflight showing quota, account/channel, required scope and upload readiness.
4. LinkedIn tool adapters:
   - ConnectSafely REST API: status/read workflows and human-reviewed comment/reaction tasks.
   - MagicPost REST API: drafts, scheduling, publishing, and metrics, gated by workspace authorization.
   - Supergrow External API: workspaces, posts, scheduling/publishing, analytics, gated by workspace authorization.
5. YouTube discovery tools:
   - Add vidIQ and TubeBuddy capability placeholders and documented deep links.
   - Do not call private/undocumented endpoints or browser scrape. Enable direct API sync only after a vendor-supported contract is confirmed.
6. 5,000-view target:
   - Per-video target default 5,000.
   - Measure source-reported views, gap, attainment and 24h/72h/7d trend.
   - Use compliant distribution: LinkedIn native post, YouTube Shorts, owned email/community channels, relevant human sharing, and separately attributed paid promotion when client-authorized.
   - Never buy views, exchange views, use bots, or promise the target.
7. Observability:
   - Publish event correlation from approval -> provider post ID -> provider URL -> distribution tasks -> measured outcomes.
   - Persist retries and idempotency keys for all provider operations.
   - Per-provider rate limits, timeout handling, circuit breakers and audit events.
8. Security:
   - Secrets only in backend environment/secret store; never send them to UI, logs or chat.
   - Status responses show configured/verified only, never values.
   - Provider write actions require per-workspace authorization and explicit approval.
9. CI:
   - Unit tests for capability validation, provider status, approval gates, upload preflight, retries and view target arithmetic.
   - Add automated workflow; release only on green run.

## Acceptance criteria (10/10 client scorecard)
- LinkedIn personal post can publish after approval and shows a verified live post URL.
- Company Page publish is enabled only with approved scope and admin permission; otherwise blocked with actionable reason.
- YouTube upload can complete end-to-end after OAuth re-consent, with a real video ID and status.
- Schedule and publish times use the channel/workspace timezone and handle provider errors idempotently.
- ConnectSafely, MagicPost and Supergrow are individually health-checked with verified capabilities.
- vidIQ and TubeBuddy show honest status; no fabricated connected state.
- Each video has a 5,000-view target and source-based 24h/72h/7d progress.
- Engagement tasks are genuine, contextual and user-reviewed; no pods, coordinated likes or unattended comments.
- All publish, scheduling, retry, API and approval operations are audited.
- CI test suite passes and a real runtime deployment is smoke-tested before release is marked production-ready.

A code release is not equivalent to live deployment. The v1.6.0 tag must be created only after the implementation is complete, CI is green, OAuth scopes are re-consented, and runtime acceptance checks pass.
